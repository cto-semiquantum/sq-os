Getting Started
Quick Start
Boot SQ-OS in under 60 seconds
ℹ️

Prerequisites: NASM, Python 3, i686-elf cross-compiler, QEMU installed and available in PATH.

  1. 1

    Clone / Open the project

    Navigate to the SQ-OS project directory in your terminal.

    CMD / POWERSHELL 
    cd C:\Users\Harsh\OneDrive\Desktop\SQ-OS
  2. 2

    Build the OS image

    Run the build script. It compiles all C and ASM files, links the kernel, and produces os.img.

    BATCH 
    .\build.bat

    Expected output: Build Successful: os.img

  3. 3

    Launch in QEMU

    Run QEMU with the 1.44MB floppy image and 32MB RAM. The GUI desktop will appear in a new window.

    POWERSHELL 
    qemu-system-i386 -drive format=raw,file=os.img -m 32M
  4. 4

    Explore the Desktop

    The SQ-OS GUI boots with a taskbar, start menu, and clock. Click the SQ button or open the Terminal to start using it.

Build System
Build Guide
How build.bat compiles and links SQ-OS
🔧
Toolchain Required

NASM — Assembles .asm files to flat binaries and ELF32 objects

i686-elf-gcc — Cross-compiler that produces 32-bit freestanding C objects (no libc, no OS ABI)

i686-elf-ld — Links all .o files into kernel.bin using linker.ld

Python 3 — Runs gen_wallpaper.py and embed_apps.py helper scripts

QEMU — Emulates an i386 PC to boot the OS image
📋
Build Steps (in order)

Step 0 — Generate wallpaper pixel data (gen_wallpaper.py)

Step 1 — Assemble boot.asm → boot.bin (512-byte MBR)
         Assemble hello.asm + crash.asm → flat PIC binaries

Step 2 — Assemble entry.asm → entry.o (ELF32)

Step 3 — Compile all 26 C source files → .o objects

Step 4 — Link everything → kernel.bin

Step 5 — Concatenate: boot.bin + kernel.bin → os.img

Step 6 — Pad to 1.44MB (2880 sectors × 512 bytes)

Step 7 — Embed app binaries at sector 120+ (embed_apps.py)
KEY COMPILER FLAGS 
CFLAGS = -c -m32 -ffreestanding -fno-pie -fno-stack-protector -O2 -Iinclude -Idrivers -Ifs -Ikernel

; -m32              → 32-bit i386 output
; -ffreestanding    → No libc, no OS runtime
; -fno-pie          → No position-independent code (flat binary)
; -fno-stack-protector → No stack canaries (no libc support)
; -O2               → Optimised code
💡

Tip: If QEMU is running when you build, the build will fail because os.img is locked. Close QEMU first, then run .\build.bat.

Running the OS
QEMU launch options and debug modes
STANDARD LAUNCH 
# Normal GUI boot
qemu-system-i386 -drive format=raw,file=os.img -m 32M

# From PowerShell (non-blocking, separate window)
Start-Process qemu-system-i386 -ArgumentList "-drive format=raw,file=os.img -m 32M"

# Debug mode: log all CPU interrupts to qemu.log
qemu-system-i386 -drive format=raw,file=os.img -m 32M -d int -D qemu.log

# Serial console output
qemu-system-i386 -drive format=raw,file=os.img -m 32M -serial file:serial.log

# With network (for ping/http)
qemu-system-i386 -drive format=raw,file=os.img -m 32M -net nic,model=ne2k_pci -net user
⚠️

Session 0 Isolation: On Windows, running QEMU from a background agent/service creates the window in Session 0 (invisible). Always launch QEMU from your own interactive terminal window.

Development Tutorial
"Hello World" C Tutorial
Write, compile, and run your first Ring 3 user application on SQ-OS

SQ-OS provides a fully isolated user space environment (Ring 3). With the new C SDK, you can write standard C programs, compile them into standard ELF executables, and run them directly in our multitasking shell.

  1. 1

    Create the Source File

    Create a file named hello.c in the apps/ directory. Use the SQ-OS header file to access system APIs:

    C (apps/hello.c)
    #include <sqos.h>

int main() {
    sq_print("Hello, SQ-OS Developer!");
    sq_sleep(1000); ; Sleep for 1000ms (1 second)
    sq_print("Clean exit via syscall...");
    sq_exit(0);     ; Exits and cleans up memory
    return 0;
}
  2. 2

    Compile using the SQ SDK

    Open your command line and run the sqbuild.bat script inside the sdk/ folder. This script compiles the source, links the startup stubs, and builds the ELF executable.

    WINDOWS BATCH / CMD
    .\sdk\sqbuild.bat apps\hello.c hello.elf

    Output: [SQ SDK] Successfully built hello.elf!

  3. 3

    Embed into the App Store

    Add "hello.elf" to the apps list in assets/embed_apps.py and run the build pipeline (build.bat) to rebuild the floppy disk image with the new binary.

  4. 4

    Run on the OS

    Boot SQ-OS in QEMU, launch the Terminal app, and type:

    SQ-OS TERMINAL
    SQ> run HELLO.ELF

    The program will execute in user mode, print its strings, sleep, and terminate cleanly!

SDK Guide

void sq_print(const char *str)
Outputs a null-terminated string to the GUI terminal history log. Deferenced safely by kernel.
void *sq_malloc(size_t size)
Allocates 8-byte aligned memory from the user-space heap. Maps physical heap pages dynamically.
void sq_free(void *ptr)
No-op in v1. Since each process memory space is isolated, all allocated heap blocks are cleaned up automatically upon exit.
uint32_t sq_time(int *h, int *m)
Reads current CMOS Real-Time Clock hours and minutes. Returns (hours << 8) | minutes.
void sq_sleep(uint32_t ms)
Yields CPU control. Marks process state as sleeping for the equivalent number of 55ms timer ticks.
void sq_exit(int code)
Terminates the process, triggers cleanup of all page table structures, and schedules the next runnable process.
Kernel Architecture
Developer & Loader Guide
How user-space binaries are managed, isolated, and executed
🧠
Process Virtual Memory Isolation
When loading an ELF binary, the kernel allocates a separate 4KB page directory. The first 4MB (Kernel region, 0x00000000 - 0x003FFFFF) is shared to allow interrupts and syscalls. The second 4MB (User region, 0x00400000 - 0x007FFFFF) is mapped to physical pages allocated from the heap. On context switch, loading the page directory address into CR3 dynamically switches user space mappings, preventing any process from corrupting another.
🏗️
ELF Segment Loading
The ELF parser reads the Elf32_Ehdr and loops through the Program Headers (Elf32_Phdr). For every segment marked as PT_LOAD (typically .text, .data, and .rodata):

1. Dynamic page table entries are allocated and mapped.
2. Segment contents are copied to their target virtual load addresses (e.g., 0x00500000).
3. Uninitialized data (.bss) is zero-initialized.
4. A user stack is mapped at 0x007FF000 (extending up to 0x00800000).
Ecosystem & Distribution
SQ Package Manager (sqpkg)
Distribute, install, and execute applications dynamically in SQ-OS

The sqpkg system introduces package management and application distribution to SQ-OS. Users can query a remote HTTP repository, download packaged applications, verify them, install them to the FAT12 disk, create desktop shortcuts, and execute them in Ring 3.

📁
SQPKG Archive Format (SQF\0)
Packages are archived using our custom, extremely lightweight sequential binary format:

[Magic: 'SQF\0' (4B)] - File block signature.
[Size: uint32_t (4B)] - Little-endian size of file data.
[Name: char[32] (32B)] - Null-padded uppercase filename.
[Data: size bytes] - Raw binary payload.

This layout allows the kernel to unpack multiple files (ELF, BMP, JSON) sequentially without complex decompression libraries.
☁️
Repository System
The SQ Repository resides at http://repo.sqos.dev/ (mapped by the DNS resolver to the host machine gateway 10.0.2.2). It contains:

1. packages.txt: Plain-text database of packages in the format [name] [file_name] [description].
2. packages/*.sqpkg: Packed archives containing the executables.
Command Description & Behavior
sqpkg update
Downloads packages.txt from the repository and writes it to PACKAGES.TXT on the FAT12 disk.
sqpkg search <query>
Performs a case-insensitive search across the locally cached database and prints matches.
sqpkg install <package>
Downloads the package archive from the remote server, validates headers, unpacks files to the FAT12 root directory, and registers desktop icons.
sqpkg remove <package>
Locates the installed package executable and marks it deleted (0xE5) in the FAT12 root directory.
sqpkg list
Scans the root directory sector of the FAT12 volume and displays all installed package binaries (*.ELF).
Quality Assurance
Regression Checklist
At this scale, preventing bugs is crucial. Verify these check-points on every clean build.

✅ Milestone Regression Checklist

  • [ ] QEMU Boot: System successfully loads bootloader, enters Protected Mode, and boots to the GUI desktop shell.
  • [ ] GUI Shell: Taskbar is visible, the clock ticks in HH:MM:SS, and start menu buttons click smoothly.
  • [ ] PS/2 Mouse: Mouse cursor moves smoothly across the screen, window dragging works, and focus highlights shift.
  • [ ] Scheduler Preemption: Multiple apps (e.g., Snake and Terminal) can run simultaneously in windowed mode.
  • [ ] ELF Application Loading: Running run HELLO.ELF executes Ring 3 instructions and exits cleanly.
  • [ ] Memory Cleanups: Heap stats (mem) confirm that terminated process stacks, directories, and segments are freed.
  • [ ] Ring 3 Isolation: Running run CRASH.APP segment faults and closes safely without triggering a kernel panic.
  • [ ] TCP/IP Stack: Running ping 10.0.2.2 responds successfully, and browser fetches HTTP responses.

Architecture Deep Dive
Ring 3 User Mode
How x86 privilege separation works in SQ-OS
🔒
How Ring 3 Entry Works
When a Ring 3 process is first scheduled, the kernel stack contains a fake iret frame with CS=0x1B (DPL=3). timer_isr does popad then iret. The CPU sees the CPL change (0→3), pops SS and ESP from the iret frame, switches to the user stack, and jumps to the entry point in Ring 3. No special jump instruction needed — just iret!
KERNEL STACK LAYOUT (Ring 3 process, first run)
; p->esp points here (lowest address)
[EAX=0] [ECX=0] [EDX=0] [EBX=0]  ← pushad
[ESP=0] [EBP=0] [ESI=0] [EDI=0]
EIP   = entry_point   ← iret pops first
CS    = 0x1B          ← Ring 3 code (DPL=3)
EFLAGS= 0x0202        ← IF=1 (interrupts on)
ESP3  = user_stack_top ← CPU switches stack
SS    = 0x23           ← Ring 3 data (DPL=3)
💥
How Page Fault Crash Works
When Ring 3 code accesses an invalid address, the CPU raises #PF (INT 14). It reads TSS.esp0 (updated per context switch), switches to the kernel stack, and calls page_fault_isr. The handler checks error_code bit 2 (user mode fault), terminates the process, and forces a reschedule. The kernel never crashes.
FAULT FLOW
Ring 3 app: mov [0xC0000000], eax  ← #PF
CPU: reads TSS.esp0 → switches to kernel stack
CPU: pushes SS3, ESP3, EFLAGS, CS, EIP, ErrorCode
page_fault_isr:
  → page_fault_handler(error_code, cr2)
    → terminates process, prints crash msg
    → returns 0 (ring 3, handled)
  → scheduler_switch(current_esp)
    → picks next READY process
  → update_tss_esp0()
  → mov esp, new_esp
  → popad + iret → kernel survives!

Development
Syscall Table
All syscalls are invoked via int 0x80 with EAX = syscall number
CALLING CONVENTION (x86 int 0x80)
; EAX = syscall number
; EBX = arg1, ECX = arg2, EDX = arg3, ESI = arg4, EDI = arg5
; Return value in EAX after syscall returns

; Example: SYS_PRINT
mov eax, 1            ; SYS_PRINT
mov ebx, message      ; pointer to string
int 0x80

; Example: SYS_EXIT (Ring 3 only — use this, NOT int 0x20)
mov eax, 5            ; SYS_EXIT
xor ebx, ebx          ; exit code 0

EAXNameArgsReturnsNotes
0 — — — Unused
1 SYS_PRINT EBX = const char* 0 Print string to GUI terminal
2 SYS_MALLOC EBX = size_t void* ptr Allocate heap memory (kmalloc)
3 SYS_FREE EBX = void* 0 Free heap allocation (kfree)
4 SYS_TIME EBX=int* h, ECX=int* m (h<<8)|m Read RTC time (hours, minutes)
5 SYS_EXIT EBX = int code — Terminate current process. Ring 3 apps must use this!
6 SYS_SLEEP EBX = uint32 ticks 0 Sleep for N PIT ticks (~55ms each). State→SLEEPING until ticks expire.
